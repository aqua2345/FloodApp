# Паводок72 — ИИ-консультант по вопросам паводковой обстановки

Мобильное приложение с ИИ-чат-ботом, которое помогает жителям Тюменской области получать актуальную информацию о паводковой обстановке, эвакуации, пунктах временного размещения (ПВР) и действиях при угрозе ЧС.

Проект состоит из двух частей:

- **frontend** — мобильное приложение под Android (Kotlin, Jetpack Compose);
- **backend** — сервер на FastAPI с RAG-модулем (retrieval-augmented generation), который обрабатывает обращения граждан и формирует ответы с помощью LLM.

> Проект разработан в рамках выпускной квалификационной работы (ВКР).

## Возможности

- 💬 Чат с ИИ-консультантом по вопросам паводков, эвакуации и ЧС на территории Тюменской области.
- 🎙 Голосовой ввод вопросов (Speech-to-Text) и озвучивание ответов (Text-to-Speech).
- 📍 Определение геопозиции пользователя и учёт её в ответах ассистента (в каком районе он находится, какая там обстановка).
- 🗺 Построение маршрута до трёх ближайших пунктов временного размещения (ПВР) с расчётом расстояния (геокодирование адресов, формула гаверсинусов).
- 🗺 Встроенная интерактивная карта паводковой обстановки (гидропосты, перекрытые дороги, ПВР, пункты сбора гуманитарной помощи) — прямо в приложении, во WebView.
- 📚 Раздел с инструкциями (что делать при паводке, какие документы взять при эвакуации, первая помощь пострадавшему в воде, телефоны горячих линий и т.д.).
- 🧭 Онбординг при первом запуске.
- 💾 История переписки хранится локально на устройстве (Room), доступны несколько чатов и их удаление.
- 🤖 ИИ-роутер запросов: определяет, относится ли вопрос к теме паводков, нужно ли парсить актуальные данные с сайта паводок72.рф, нужно ли строить маршрут — и отклоняет вопросы не по теме.
- 🌐 Гибридный источник знаний: локальная база (текстовые файлы с инструкциями и данными по ПВР) + живой парсинг официального сайта и ГИС-портала Тюменской области.

## Архитектура

```
┌─────────────────────────┐        HTTP (POST /chat)        ┌──────────────────────────┐
│   Android-приложение     │ ───────────────────────────────▶ │        FastAPI backend    │
│  (Kotlin, Jetpack        │                                  │                            │
│   Compose, Retrofit)     │ ◀─────────────────────────────── │  RAG-движок (FloodAssistant)│
└─────────────────────────┘        JSON (ответ + маршрут)     └──────────────────────────┘
                                                                          │
                                                     ┌────────────────────┼─────────────────────┐
                                                     ▼                    ▼                      ▼
                                          Локальная база знаний   Парсинг паводок72.рф   LLM (через OpenAI-совместимое API)
                                             (data/*.txt,          и ГИС-портала 72to.ru   + геокодирование (2GIS / Яндекс)
                                          поиск через FAISS +
                                          мультиязычные эмбеддинги)
```

Общая логика обработки запроса на backend:

1. Определяется район пользователя по координатам (если переданы) через обратное геокодирование 2GIS.
2. ИИ-роутер (LLM) анализирует намерение пользователя: относится ли вопрос к теме паводков, нужно ли построить маршрут, какие районы затронуты.
3. Если запрос не по теме — бот вежливо отказывает, не тратя вызов основной модели.
4. Если это запрос маршрута — ищутся ближайшие ПВР (с геокодированием и кэшированием координат) и данные для построения маршрута возвращаются клиенту.
5. Иначе — собирается контекст из локальной базы знаний (поиск по эмбеддингам через FAISS) и, при необходимости, свежих данных с сайта паводок72.рф и ГИС-портала.
6. Собранный контекст передаётся в LLM вместе с системным промптом, ответ возвращается клиенту.

## Технологический стек

**Backend:**
- Python, FastAPI, Uvicorn
- OpenAI-совместимый клиент (`openai` SDK) для обращения к LLM
- `sentence-transformers` (`paraphrase-multilingual-MiniLM-L12-v2`) — эмбеддинги для поиска по базе знаний
- `faiss` — векторный поиск (индекс `IndexFlatL2`)
- `requests` + `BeautifulSoup4` — парсинг данных с сайта паводок72.рф и ГИС-портала 72to.ru
- Геокодирование через API 2GIS (основной провайдер) и Яндекс.Геокодер (резервный)

**Frontend (Android):**
- Kotlin, Jetpack Compose (Material 3)
- Retrofit + Gson — работа с backend API
- Room — локальное хранение истории чатов
- Google Play Services Location — геолокация
- Android SpeechRecognizer / TextToSpeech — голосовой ввод и озвучивание ответов
- WebView — встраивание интерактивной карты ГИС-портала

## Backend

### Как это работает

- **`main.py`** поднимает FastAPI-сервер с единственным основным эндпоинтом `/chat`, который принимает сообщение пользователя (и опционально координаты) и возвращает ответ ассистента, а при необходимости — данные для построения маршрута.
- **`rag_engine.py`** — ядро системы (`FloodAssistant`):
  - загружает и индексирует локальную базу знаний (`data/*.txt`) с помощью эмбеддингов и FAISS;
  - ИИ-роутер на базе LLM определяет тип запроса (в теме/не в теме, нужен ли парсинг, это ли маршрут);
  - для маршрутов — геокодирует адрес пользователя, находит 3 ближайших ПВР (расчёт через формулу гаверсинусов), кэширует геокодированные координаты на диск;
  - формирует финальный промпт из данных базы знаний и/или свежих данных с сайта и отправляет его в LLM;
  - ведёт историю диалога по `chat_id` и пишет подробные debug-логи каждого запроса в `logs/`.
- **`flood_parser.py`** — парсер сайта паводок72.рф (постранично по районам) и разделов ГИС-портала 72to.ru (перекрытые/открытые дороги, гидропосты, пункты сбора гуманитарной помощи, вакцинация), с кэшированием результатов на определённое время (TTL).

### API

**`GET /`**
Проверка, что сервер запущен.

**`POST /chat`**

Тело запроса:
```json
{
  "message": "Что делать при угрозе паводка?",
  "chat_id": "default",
  "lat": 57.15,
  "lon": 65.53
}
```

Ответ:
```json
{
  "response": "Текст ответа ассистента",
  "route_data": {
    "type": "pvr_selection",
    "user_location": { "lat": 57.15, "lon": 65.53 },
    "destinations": [
      {
        "name": "Название ПВР",
        "address": "Адрес",
        "district": "Район",
        "lat": 57.16,
        "lon": 65.50,
        "distance_km": 2.3,
        "phone": "+7...",
        "capacity": 100
      }
    ]
  }
}
```
Поле `route_data` присутствует только для ответов, связанных с построением маршрута до ПВР — в остальных случаях оно равно `null`.

### Установка и запуск backend

1. Перейти в папку backend:
   ```bash
   cd backend
   ```
2. Установить зависимости (файла `requirements.txt` в репозитории нет — нужно установить пакеты вручную):
   ```bash
   pip install fastapi uvicorn pydantic openai sentence-transformers faiss-cpu numpy requests beautifulsoup4
   ```
3. Указать актуальные API-ключи (см. раздел [API-ключи и конфигурация](#api-ключи-и-конфигурация)).
4. Запустить сервер:
   ```bash
   python main.py
   ```
   Сервер поднимется на `http://0.0.0.0:8000`.

## Frontend (Android)

### Экраны приложения

- **Онбординг** — краткое знакомство с возможностями приложения при первом запуске.
- **Чат** — основной экран общения с ассистентом: текстовый и голосовой ввод, поддержка нескольких чатов, история сообщений.
- **Карта** — встроенная интерактивная карта паводковой обстановки Тюменской области (ГИС-портал 72to.ru).
- **Инструкции** — справочные материалы на случай паводка (действия при паводке, документы при эвакуации, первая помощь и др.).
- **Маршрут до ПВР** — при запросе маршрута бот показывает 3 ближайших пункта временного размещения с адресом, расстоянием, вместимостью и телефоном.

### Установка и запуск frontend

1. Открыть папку `frontend` в Android Studio.
2. Указать адрес backend-сервера в `ChatApiService.kt` (константа `BASE_URL`) — по умолчанию там прописан IP-адрес сервера, использовавшегося при разработке; замените его на адрес своего запущенного backend.
3. Синхронизировать Gradle и собрать проект (минимальный SDK — 24, целевой — 36; Java/Kotlin JVM target — 21).
4. Запустить на эмуляторе или физическом устройстве. Для работы приложению потребуются разрешения: геолокация (`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`), интернет и запись аудио (для голосового ввода).

## API-ключи и конфигурация

В коде backend (`rag_engine.py`) на данный момент используются захардкоженные ключи для:
- доступа к LLM (через OpenAI-совместимый API);
- геокодера 2GIS / Яндекс.Геокодера.

**Эти ключи в текущем виде недействительны** и оставлены в коде только как пример структуры конфигурации. Для запуска проекта необходимо:
1. Сгенерировать собственные ключи в соответствующих сервисах (провайдер LLM-API, 2GIS, при необходимости — Яндекс.Геокодер);
2. Заменить ими значения в `rag_engine.py` (рекомендуется вынести их в переменные окружения / `.env`-файл вместо хранения в коде).

Также в `frontend/.../ChatApiService.kt` указан адрес backend-сервера (`BASE_URL`), использовавшийся во время разработки — его тоже нужно заменить на актуальный адрес вашего сервера.

## Известные ограничения

- Файл зависимостей Python (`requirements.txt`) в репозитории отсутствует — список пакетов для установки приведён выше, вручную.
- Backend не имеет постоянного хранилища диалогов (история чатов хранится в памяти процесса, кроме кэша геокодирования ПВР, который сохраняется на диск).
- Приложение ориентировано на районы Тюменской области, покрытые локальной базой знаний и сайтом паводок72.рф (Абатский, Викуловский, Казанский, Тобольский, Уватский районы, г. Ишим).
